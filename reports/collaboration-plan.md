## 后续分工建议（未启动）

1. Phase 2：RVM agent 负责转换验证，研究 agent 核对导出限制，主控组织真实浏览器验证。
2. Phase 3：TXT agent 实现通用元数据解析；保留未知、重复和多行记录，支持真实文件中的后置定位命令。
3. Phase 4：研究 agent 转任对象映射；另外两名 agent 提供源索引并复核候选。
4. Phase 5：分别负责渲染、交互、树与属性；主控独占应用入口、公共接口和依赖配置。
5. Phase 6：在同一机器和浏览器、固定窗口和操作场景下记录性能，不预填结果。
6. Phase 7：仅依据实测瓶颈提出优化；更换整体技术路线需要用户确认。

## 交接与验收规则

- 每次交接提供产物位置、已验证事实、复现方式、未解决问题和接口需求。
- RVM 节点、工程对象、图元、mesh 分开计数。
- RVM ID、TXT ID 分开建立，由映射表关联；不得依赖全局数组序号强行对应。
- 同输入重复转换的稳定性与跨导出版本的稳定性分开声明。
- 无证据的类型、单位、几何覆盖或匹配结果标为未验证，不以推测填充。
- 解析完整性、几何正确性、工程语义关联和运行性能分别验收。
- 遇到核心缺失暂停受影响阶段和下游，保留问题证据；独立检查可继续。
